# Stage 8: Storage buffers, explicit layouts, GPU culling

Tag: `stage-8-gpu-culling` · Source: real

## Concepts
- Address spaces: `uniform` (small, read-only, 64 KiB guaranteed) vs `storage` (large, runtime-sized `array<T>`, `read` or `read_write`); 10k × 64 B of transforms only fits in storage
- Runtime-sized arrays: storage only, last struct member or whole binding; length from the bound buffer via `arrayLength`
- The object table moves from per-instance vertex attributes to `var<storage> model: array<mat4x4f>`, read by `instance_index`
- `instance_index` is generated by the draw: `firstInstance + 0 .. instanceCount − 1`
- Access mode belongs to the binding, not the buffer: compute writes the visible list (`read_write`), vertex reads it (`read`); vertex shaders can't write storage
- Explicit layouts: bind group layout (shape) → bind group (contents) → pipeline layout (group index → layout); sharing a group means the same layout object at the same index in both pipeline layouts
- Groups: 0 frame and 1 entity shared; 2 differs per pipeline (compute: visible list + indirect args as `storage`; render: visible list as `read-only-storage`)
- Pipeline-overridable constants (`override`): `WORKGROUP_SIZE`, `CULL_SCALE`; can size only `workgroup` arrays
- Cull pass: `atomicAdd` returns the previous value, a unique slot in the visible list; vertex reads `model[visibleList[instance_index]]`
- Counter reset: `clearBuffer(indirect, 4, 4)` before the cull pass; zeroing all 20 bytes would zero `indexCount`
- A negative value written through `Uint32Array` stores the same bits as the `i32`: one view is enough
- Clip-space point test: `|x|, |y| ≤ w`, `0 ≤ z ≤ w` (WebGPU depth 0..1); points behind the camera fail automatically
- Workgroup memory and barriers (two-level counting) discussed, not used
- Left as an exercise: frustum planes from `viewProjection` + bounding sphere, to stop edge popping

## Mistakes → rules
- Bind group creation failed with "Expected layout: []": `'auto'` layouts reflect bindings the entry point uses, not declares
- Layout order, visibility, binding types and usages all mismatched after the refactor (labels made each one readable):
  - A layout's position in `bindGroupLayouts` is its group index; lookup tables don't affect it
  - `visibility` must include every stage that uses the entry; writable `'storage'` can't include `VERTEX`
  - Layout `type` must match the shader's address space and access mode; fix the wrong side, don't add usage flags to silence it
  - A buffer's usage flags must cover every way it's bound or used
- `GroupOrder.ComputeVisibility` was `undefined` (keys were the lowercase values), so the bind group landed in group 0: `undefined` converts to index 0
- One quad on screen: cull pass not wired, so the zero-filled visible list sent every instance to `model[0]`. A missing write is object 0, not an error
- `instanceCount` grew by 10,000 per frame: atomics only go up; reset before each dispatch, since no barrier spans workgroups
- `clearBuffer` called while the compute pass was open: the encoder is locked between `begin*Pass` and `end`
- `clip.x <= clip.x` always true and `-w <= clip.z` (OpenGL range): long `&&` chains hide typos; prefer `all(abs(clip.xy) <= vec2f(w))`
- Debugging: label every GPU object; in an error cascade only the first message is the cause; "it renders" says nothing about validation, check the console
